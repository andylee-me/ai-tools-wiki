Slash Command 開發

/command-development

協助建立自訂的 Slash Command（斜線指令）；定義指令名稱、參數格式、frontmatter 與執行邏輯；與 Skill 的差異在於 Command 通常是用戶主動輸入觸發，而 Skill 可以由 Claude 主動判斷呼叫；適合建立快速操作入口。

Skill 資訊
指令
/command-development
分類
自訂擴充
觸發方式
使用者輸入 / 指令
設定格式
frontmatter + markdown
部署位置
.claude/commands/

適用時機

  • 需要一個快速觸發固定操作的快捷指令，不需要 Claude 主動判斷何時使用
  • 建立有參數的批次操作指令，讓使用者可在呼叫時傳入客製化選項
  • 統一管理多個相關指令，建立有條理的指令命名空間與目錄結構
  • 將常用的 prompt 封裝成可重複使用的指令，降低每次輸入的成本

使用方式

  1. 描述指令名稱、觸發方式與執行邏輯
    說明新指令的斜線名稱（如 /deploy）、接受哪些參數、以及執行時 Claude 應該做什麼操作或輸出什麼內容。
  2. Claude 生成 Command 定義檔
    Claude 產生包含 frontmatter（description、args 定義）與指令執行邏輯的完整 markdown 定義檔，可依需求審閱並修改。
  3. 部署至 .claude/commands/ 並測試
    將定義檔存入 .claude/commands/ 目錄，重新啟動 Claude Code 後，在對話中輸入對應的斜線指令驗證功能是否正確運作。

使用範例

範例：建立部署指令
/command-development 建立 /deploy 指令，接受 env 參數（staging 或 production）， 執行對應的部署腳本並在結束後顯示部署摘要。
範例：建立測試報告指令
/command-development 建立 /test-report 指令，執行 npm test 並將結果 整理成通過 / 失敗 / 跳過三個區塊的 Markdown 報告， 存入 ./reports/ 目錄。

注意事項

Command 與 Skill 的核心差異
Command 由使用者主動輸入觸發，Claude 不會主動推薦；Skill 則帶有 when_to_use 描述，Claude 可以在合適時機主動建議使用。若希望 Claude 自動判斷呼叫，請改用 Skill。

參數格式需明確定義
在 frontmatter 的 args 區段中明確定義每個參數的名稱、型別與是否必填。定義清晰可讓 Claude 在使用者未提供必要參數時主動詢問，提升指令的易用性。
