程式碼審查

/code-reviewer

針對 TypeScript、JavaScript、Python、Swift、Kotlin、Go 進行全面性的程式碼審查， 涵蓋安全性漏洞、效能問題、最佳實踐與程式碼風格，並附帶自動化分析與審查清單。

審查涵蓋面向

  • 安全性掃描：檢查 SQL Injection、XSS、CSRF、不安全的反序列化等 OWASP Top 10 漏洞。
  • 效能分析：找出不必要的重複計算、N+1 查詢、記憶體洩漏與過度的重新渲染。
  • 最佳實踐：確認是否遵循語言慣例、Design Pattern 的正確使用與錯誤處理完整性。
  • 程式碼品質：可讀性、命名清晰度、函數職責單一原則與不必要的複雜度。
  • 測試覆蓋率：評估現有測試是否充足，並建議補充哪些邊界案例。

使用方式

  1. 指定要審查的檔案或範圍
    可以指定單一檔案、目錄或 Git diff，例如「審查 src/auth/ 目錄下的所有檔案」。
  2. 說明審查重點（可選）
    如果有特別關注的面向（如「這段程式碼會處理用戶密碼，請特別關注安全性」），可以額外說明。
  3. 取得結構化審查報告
    Claude 以嚴重程度分級（Critical / Major / Minor）整理問題清單，並附上修正建議與程式碼範例。
  4. 追問或要求自動修正
    可以針對特定問題深入討論，或要求 Claude 直接修正某些問題（建議先從 Critical 問題開始）。

使用範例

範例 1：審查特定檔案
/code-reviewer 審查 src/api/auth.ts，這個檔案 處理使用者登入，請特別關注 安全性問題
範例 2：審查 PR 改動
/code-reviewer 審查這個 PR 的所有改動， 先列出 Critical 問題， 然後再列 Minor 建議

注意事項

先修 Critical 再修 Minor
審查結果會分成不同嚴重程度，建議優先解決安全漏洞（Critical）再處理程式碼風格（Minor），避免修改優先順序混亂。

搭配 /simplify 使用
Code Review 完成並修正問題後，可以再跑一次 /simplify 確認修改後的程式碼沒有引入新的複雜度。
