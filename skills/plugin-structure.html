Plugin 架構指南

/plugin-structure

引導建立一個完整的 Claude Code Plugin；解說 plugin.json 的設定欄位（name、description、skills、commands、hooks）、目錄組織規範（skills/、commands/、hooks/）、以及各元件的職責分工；適合想打包一組相關 Skill 並分享給他人的情境。

適用時機

  • 想將多個相關 Skill 打包成一個可分享的套件，方便他人一次安裝所有元件
  • 建立公司內部的標準 Claude 擴充集，確保所有成員使用一致的工具配置
  • 需要清晰的目錄結構組織大量自訂指令，避免 .claude/ 目錄雜亂無章
  • 準備發布或分享給社群的 Plugin，需要符合規範的完整結構與說明文件

使用方式

  1. 描述 Plugin 的整體功能定位
    說明這個 Plugin 的主題（如「前端開發工具包」或「資料科學助手」），以及目標使用者與解決的核心問題。
  2. 列出包含的 Skills / Commands / Hooks
    逐一說明 Plugin 內的每個元件名稱與功能，Claude 會根據這份清單規劃各元件的職責分工與相互關係。
  3. 生成 plugin.json 與目錄結構
    Claude 生成符合規範的 plugin.json 設定檔，包含 name、description、version、skills、commands、hooks 等欄位，並輸出建議的目錄樹狀結構。
  4. 依序建立各元件並驗證
    逐一建立 Plugin 內的 Skills、Commands 與 Hooks 定義檔，完成後將整個 Plugin 目錄放置於 .claude/plugins/ 並重新載入驗證。

使用範例

範例：建立前端開發 Plugin
/plugin-structure 我想建立一個「前端工具包」Plugin，包含： 1. /component Skill：生成 React 元件 2. /design-review Command：審查 CSS 設計 3. PostToolUse Hook：每次寫入 .tsx 後自動執行 TypeScript 型別檢查
範例：建立資料分析 Plugin
/plugin-structure 建立「資料科學助手」Plugin，包含讀取 CSV、 生成 EDA 報告與繪製統計圖表三個 Skill， 並加入 Stop Hook 自動清理暫存檔案。

注意事項

plugin.json 是 Plugin 的入口點
plugin.json 必須放在 Plugin 根目錄，並正確列出所有元件的相對路徑。若路徑有誤，Claude Code 將無法正確載入 Plugin 中的部分元件，建議完成後逐一驗證每個元件是否可正常呼叫。

版本號有助於管理更新
在 plugin.json 的 version 欄位維護語意化版本號（如 1.0.0）。當 Plugin 有破壞性變更時，升版有助於使用者識別需要重新設定或調整現有工作流程。
