Codex 任務委派

/codex:rescue

當 Claude Code 在某個任務卡關、繞圈超過三輪、或需要深度程式碼調查時，將任務委派給 Codex 子流程；Codex 以獨立視角重新審視問題，不受既有思路限制；適合「已嘗試多種方法但仍未解決」的困難情境。

Skill 資訊
指令
/codex:rescue
分類
AI 整合開發

Codex 子流程

Claude 卡關或繞圈

Bash

適用時機

  • Claude 在同一問題上繞圈超過三次，仍無法找到根本原因
  • 需要對複雜 Bug 進行第二輪獨立診斷，以排除思路盲點
  • 架構決策需要另一個觀點確認，降低單一視角的偏誤風險
  • 任務複雜度超出單一對話的合理範圍，需要更深度的調查

使用方式

  1. 描述當前卡關的問題與已嘗試的方法
    說明目前遇到的問題、已嘗試的所有解法，以及每次嘗試的結果，幫助 Codex 快速掌握現況。
  2. Claude 生成委派給 Codex 的 prompt
    Claude 將整理問題脈絡並組裝一份完整的 Codex 任務 prompt，包含必要的背景資訊與調查方向。
  3. Codex 回傳深度調查結果
    Codex 子流程以獨立視角進行調查，回傳分析報告、根本原因推斷或具體的修正建議。

使用範例

範例：委派繞圈的 Bug 調查
/codex:rescue 我在追一個記憶體洩漏問題， 已試過 WeakRef、手動 cleanup、 檢查 event listener，都沒找到根因， 請 Codex 從頭重新調查
範例：架構決策第二意見
/codex:rescue 我在考慮用 event sourcing 還是 CQRS 處理訂單狀態，已討論兩輪 但還是無法確定，請 Codex 給出 獨立評估與建議

注意事項

提供完整的嘗試歷程
委派時請盡量描述所有已嘗試的解法與結果，避免 Codex 重複相同的調查路徑，讓獨立視角的價值最大化。

與 /diagnose 的搭配使用
建議先用 /diagnose 完整跑完六步驟診斷循環，仍無法解決時再使用 /codex:rescue 進行第二輪深度調查，兩者相輔相成。
